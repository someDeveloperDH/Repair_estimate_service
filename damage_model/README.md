# 멘디 파손 검출 모델 (outsole · heel lining)

고객 사진에서 운동화 파손 **위치와 종류**를 찾는 검출 모델 작업물입니다. 지금은 파손 "정도(심각도)"는 판단하지 않습니다(아래 [다음 단계](#다음-단계) 참고).

- 클래스 2개
  - **outsole**: 밑창 쪽을 본드로 붙이는 수선이 필요한 곳
  - **heel lining**: 뒤꿈치 안감이 찢어지거나 헤진 곳
- 모델 2개를 같은 데이터·같은 채점으로 비교합니다.
  - **YOLO26s**: Ultralytics, AGPL-3.0. 앱에 넣으려면 유료 라이선스가 필요합니다.
  - **RF-DETR-S**: Roboflow, Apache-2.0. 앱에 넣을 수 있습니다.
- 학습은 Colab 무료 T4에서 합니다.

> 이 저장소에는 **사진이 없습니다.** 원본 사진(S3 `mendii-sneakers`)에는 작업지시서(개인정보)가 찍혀 있어 외부 공유 금지입니다.
> 확인 시트, CVAT export zip, S3 키도 올리지 않았습니다. 노트북은 실행할 때 S3에서 직접 받습니다.

## 라벨 기준 (2026-10-14 확정)

**outsole = 밑창 쪽을 본드로 붙이는 수선**
- 넣는 것
  - 갑피-밑창 분리: 벌어짐, 들뜸, 완전 탈락
  - 밑창 옆벽·가장자리·중창·폭싱·랜드의 찢어짐이나 갈라짐
- 빼는 것: 바닥 구멍, 닳음, 뒷굽 닳음, 바닥면 금, 갑피 찢어짐, 깔창, 안감
- 박스는 떨어지거나 찢어진 구간 전체와 위아래 여유를 덮는 넉넉한 직사각형으로 그립니다. 한 짝·한 구간마다 하나씩 그리고, 실선처럼 가늘게 그리지 않습니다.

**heel lining**: 뒤꿈치 안감 찢어짐·헤짐. CVAT 라벨러 라벨을 그대로 씁니다.

## 학습·검증 분리와 채점

- **세션 단위 분리**: 촬영 간격 300초 이하를 한 세션(대개 신발 한 켤레)으로 묶고, 세션 단위로 20%를 검증으로 뺍니다. 같은 신발 사진이 학습과 검증에 섞이지 않습니다.
- **같은 검증 사진 유지**: 첫 학습(`yolo26s_1024`)의 검증 세션을 그대로 두고, 새로 검수된 세션에서만 20%를 더합니다. `split.json`은 Drive에 저장해 RF-DETR 노트북이 그대로 씁니다.
- **음성**: 파손 사진과 1:1로 넣습니다. 순서는 재라벨에서 지운 오답 → 같은 신발에서 "파손 없음"으로 확인한 사진 → 무작위입니다.
- **outsole 사진은 학습에 2번** 넣습니다(드문 클래스 반복 샘플링).
- **검증으로 모델을 고르지 않습니다**: 학습 중에는 검증하지 않고 마지막 가중치로 채점합니다(YOLO `last.pt`, RF-DETR `last_ema.pth`).
- **채점 지표**
  - 박스 AP50, AP50-95. outsole은 범위가 사람마다 달라 AP30도 같이 봅니다.
  - 사진 단위: 파손 사진을 찾았는지, 파손 없는 사진에 잘못 경보를 냈는지
  - **신발(세션) 단위**: 한 장이라도 찾으면 찾은 것으로 봅니다. 앱이 실제로 판단하는 방식입니다.
  - 정답 박스 크기별 찾은 비율
  - RF-DETR 노트북은 두 모델 AP50 차이의 **세션 부트스트랩 90% 구간**을 냅니다. 구간이 0을 걸치면 우연일 수 있는 차이입니다.

## 실행 (Colab)

1. 런타임을 **T4 GPU**로 바꾸고 모두 실행합니다. 3번 셀에서 파일 3개를 올립니다. `MyDrive/mendii/yolo26_damage/`에 미리 넣어 두면 그 단계를 건너뜁니다.
   - CVAT 최종 export zip
   - `labels/outsole_relabel.json`
   - S3 읽기 전용 키 csv(또는 Colab 비밀 `AWS_ACCESS_KEY_ID`·`AWS_SECRET_ACCESS_KEY`)
2. **YOLO26 노트북**을 먼저 돌립니다. yolo26s·1024px·60 epoch, T4에서 약 3.5~4시간입니다.
3. 그다음 **RF-DETR 노트북**을 돌립니다. 처음에는 `QUICK_TEST = True`로 약 5분 시험한 뒤 본 학습을 합니다.
   - RF-DETR-S·768px·20 epoch, 추정 3.5~5시간입니다.
   - 같은 Drive 폴더의 사진 캐시와 `split.json`, YOLO `last.pt`를 써서 비교표를 냅니다.
4. 끊기면 3번 셀에서 `RESUME = True`로 바꾸고 모두 실행합니다.
5. 결과는 Drive `runs/<NAME>/summary.json`에 저장되고, 셀 맨 아래에 JSON 한 줄로도 나옵니다.

노트북은 `ultralytics==8.4.169`, `rfdetr[train]==1.11.2`로 버전을 고정했습니다.

## 모델 선택 메모

| | YOLO26s | RF-DETR-S |
|---|---|---|
| 파라미터 / 계산량(COCO) | 9.5M / 20.9 GFLOPs @640 | 32.1M / 59.8 GFLOPs @512 |
| 우리 설정 계산량 | 약 54 GFLOPs (1024px) | 약 135 GFLOPs (768px) |
| COCO AP / 작은 물체 AP | 48.6 / 29.5 | 53.0 / 32.0 |
| 라이선스 | AGPL-3.0. 직접 학습한 가중치도 AGPL로 보며, Enterprise는 유료·가격 비공개 | Apache-2.0 (N~L. XL·2XL은 PML) |

- RF-DETR은 N·S·M·L 모두 DINOv2 뼈대를 써서 파라미터가 거의 같고, 크기는 주로 입력 해상도로 나뉩니다. 파라미터 수보다 계산량과 입력 크기가 속도를 정합니다.
- **결정 규칙**: 같은 검증에서 성능이 비슷하면 RF-DETR을 씁니다. YOLO가 확실히 이길 때(90% 구간이 YOLO 쪽)만 라이선스를 검토합니다.
- 그 밖의 Apache 대안은 D-FINE, DEIM v1입니다. DEIMv2는 2026-08부터 비상업 라이선스로 바뀌었습니다.
- **SAM**
  - SAM 1, SAM 2.1, HQ-SAM은 Apache라 라벨링 보조와 부위(분모) 윤곽 따기에 씁니다.
  - 얇은 밑창 틈의 윤곽, 글자로 파손을 바로 찾는 SAM 3 zero-shot은 근거가 약합니다.
  - SAM 3는 Meta 자체 라이선스이고 맥 CPU 서빙에는 무겁습니다.

## 재라벨 도구 사용법 (`relabel_tools/`)

작업 폴더(`D`) 구조는 `img/`(2048px 사진), `cur_boxes.json`(지금 라벨), `chunks.json`(묶음), `results/`(기록)입니다.

```bash
python fetch.py D                      # targets.json의 사진을 S3에서 받아 2048px로 저장 (키는 환경변수)
python todo.py 0                       # 묶음 0에서 아직 기록 안 한 사진
python view.py 20240102_085928.jpg cur # 1000px + 20×20 격자 + 지금 박스
python zoom.py 20240102_085928.jpg 5 10 15 18
python record.py 0 20240102_085928.jpg modify "8.5,8.3,13.2,18.3" "foxing peeled"
python changed.py 0                    # 검증할 사진(바뀐 것 + uncertain)
python compile.py out.json             # 검증 결과 우선으로 합쳐 0~1 좌표 json
python sheets.py out.json sheets/      # 바뀐 사진 확인 시트 (로컬 전용, 사진 포함이라 공유 금지)
```
