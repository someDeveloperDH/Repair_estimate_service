작성일: 2026-10-14

두 task의 데이터, 모델, 학습, 인퍼런스, 평가, 학습 전후 EDA 설계를 한 문서에 정리했습니다. 현재 작성된 코드의 동작과 향후 확장 계획을 구분하며, 목표 수치는 실측 성능이 아닌 초기 프로젝트 기준입니다.

## 1. 전체 구조와 설계 방향

| 항목 | Task 1 — data1 | Task 2 — data2 |
|---|---|---|
| 질문 | 사진에 어떤 종류의 신발이 어디에 있는가? | 운동화 손상 부위가 어디에 있고 어떤 부위인가? |
| 학습 형태 | 바운딩 박스 객체 탐지 | 바운딩 박스 객체 탐지 |
| 예측 단위 | 신발 객체 | 손상 부위 객체 또는 예외 객체 |
| 기본 클래스 | 신발 종류 7개 | 손상 부위 2개 + not_sneakers |
| 기본 모델 | YOLO11n 사전학습 탐지 모델 | YOLO11n 사전학습 탐지 모델 |
| 가중치 | data1 전용 best.pt | data2 전용 best.pt |
| 평가 우선순위 | 신발 종류를 균형 있게 구분하고 운동화를 놓치지 않기 | 손상 부위 미탐을 줄이고 위치를 정확히 찾기 |

원본 라벨에 객체 위치가 있으므로 이미지 전체를 하나의 클래스로 분류하는 방식 대신 객체 탐지를 사용합니다. 두 모델은 독립적으로 학습·평가합니다. task별 실행 파일은 분리하고 실제 처리와 평가 계산은 공통 모듈로 관리합니다.

```text
원본 사진 ZIP + task별 COCO 라벨
              ↓ 파일명 매칭·좌표 정규화·날짜별 분할
       task별 YOLO 학습 데이터
              ↓
       학습 전 EDA 및 라벨 검토
              ↓
       task별 YOLO11n 미세조정
              ↓
       val 평가·confidence 선택
              ↓
       val 결과 EDA·모델 개선
              ↓ 모델·설정 확정
       test 평가·test 결과 EDA
              ↓
       새 사진 인퍼런스
```

## 2. 공통 데이터 설계

### 원본 매칭과 변환

- 원본 사진은 `raw/pic.zip`, 라벨은 task별 ZIP 내부 `annotations/instances_default.json`을 사용합니다.
- 이미지 파일명으로 사진과 라벨을 매칭합니다. 이름 중복은 오류로 처리하며, 누락 사진 목록을 저장합니다.
- COCO 클래스 ID를 0부터 시작하는 YOLO ID로 변환합니다.
- COCO 박스 `[x, y, width, height]`를 YOLO의 `class_id center_x center_y width height`로 변환합니다. 좌표는 라벨 JSON에 기록된 이미지 너비·높이로 정규화합니다.
- 이미지와 라벨의 종횡비를 확인하고, 박스가 이미지 경계를 벗어나면 경계로 자릅니다. 사진 자체는 재인코딩하지 않습니다.
- 라벨이 없는 사진은 정상 사진과 미작업 사진을 구분할 수 없어 제외합니다. 정상으로 확인된 음성 표본을 별도로 확보해야 합니다.

### 분할 원칙

파일명 앞 8자리 촬영 날짜를 그룹으로 묶고, 날짜 해시를 사용해 약 80/10/10의 train/val/test 버킷에 배정합니다. 같은 날짜는 두 task에서 같은 split에 들어갑니다. 연속 촬영 사진이 평가에 섞이는 것을 줄이기 위한 선택입니다.

날짜별 사진 수가 다르므로 실제 이미지 비율은 정확히 80/10/10이 아닙니다. 다른 날짜에 같은 신발이 등장하는 경우까지 차단하지는 못합니다. 학습 전 동일 파일 해시와 동일 dHash 후보를 확인하고, 분할 변경이 필요하면 학습 전에 새 버전으로 확정합니다.

## 3. Task 1 — 신발 종류 탐지 설계

### 데이터와 출력

| YOLO ID | 클래스 | 의미 | 최종 박스 수 |
|---:|---|---|---:|
| 0 | sneakers | 운동화 | 8,479 |
| 1 | formal | 구두·정장화 | 578 |
| 2 | boots | 부츠 | 1,176 |
| 3 | sandals | 샌들 | 233 |
| 4 | slippers | 슬리퍼 | 67 |
| 5 | heels | 하이힐 | 114 |
| 6 | others | 기타 신발 | 265 |
| | **합계** | | **10,912** |

원본 등록 8,754장 중 라벨 없는 3,008장을 제외하여 **5,746장**을 사용합니다. 원본 사진 누락은 없습니다. train 4,368장, val 557장, test 821장입니다. 사용 사진은 512×512가 5,741장, 512×683이 5장입니다. 경계를 벗어난 박스 4개를 잘랐습니다.

출력은 이미지 안의 신발별 `클래스, confidence, 박스 좌표`입니다. 여러 신발이 있으면 여러 객체를 반환합니다.

### 학습 설계

YOLO11n의 사전학습 가중치로 7개 클래스를 미세조정합니다. 작은 모델로 기준 성능과 자원 사용량을 확인한 후, 검증 성능이 부족하면 YOLO11s를 비교합니다. 현재 기본 코드는 클래스별 가중치나 소수 클래스 재표집을 적용하지 않습니다. 불균형에 대한 개선은 기준 실험의 클래스별 결과를 확인한 뒤 별도 실험으로 추가합니다.

신발 전체 모양을 보존하도록 약한 회전·이동·크기·밝기·색상 변화를 사용합니다. 좌우 반전 확률은 0.5, mosaic 확률은 0.3이며 mixup과 상하 반전은 사용하지 않습니다.

### 인퍼런스 설계

data1 전용 best.pt와 val에서 선택한 confidence를 사용합니다. 박스와 클래스명을 그린 이미지/영상, 예측 JSONL, YOLO 라벨을 저장합니다. JSONL 좌표는 원본 입력 사진 기준 `xyxy`입니다. 새 사진 전체에서 신발을 탐지하며, 출력 박스가 곧 이미지 전체 분류 결과인 것은 아닙니다.

### 평가와 초기 목표

| 지표 | 목표 | 이유 |
|---|---:|---|
| 7종 mAP@0.5 | ≥ 90% | 종류별 종합 탐지 성능 |
| 7종 mAP@0.5:0.95 | ≥ 65% | 박스 위치 정확도까지 확인 |
| Macro-Precision | ≥ 90% | 클래스별 오탐 억제 |
| Macro-Recall | ≥ 90% | 클래스별 미탐 억제 |
| Macro-F1 | ≥ 90% | 오탐과 미탐의 균형 |
| sneakers Recall | ≥ 95% | 후속 운동화 손상 탐지에 필요한 입력 누락 최소화 |

confidence는 val에서 sneakers Recall 95%를 만족하는 후보 중 지원 클래스 Macro-F1이 가장 높은 값을 선택합니다. 지원 클래스는 정답이 있는 클래스를 뜻하며 평균에 포함한 클래스 목록을 저장합니다.

현재 slippers는 val 정답 0개·test 1개, heels는 test 1개, sandals는 test 14개입니다. 따라서 7종 전체에 대한 최종 합격 판정은 보류하고 독립 평가 데이터를 보강합니다. 모델의 전체 평균만 보고 소수 클래스가 잘 동작한다고 판단하지 않습니다.

### 학습 전후 EDA

학습 전에는 운동화 편중, 소수 클래스의 날짜·분할 분포, 신발 박스 크기·위치, 이미지당 객체 수, 중복 후보와 라벨 샘플을 확인합니다.

학습 후에는 클래스별 AP·Precision·Recall·F1과 혼동행렬을 확인하고, 종류 혼동과 위치 오류를 구분합니다. 특히 운동화 미탐과 소수 클래스 오류를 검토합니다. 손실·mAP 곡선으로 학습 불안정과 과적합을 확인합니다.

## 4. Task 2 — 운동화 손상 부위 탐지 설계

### 데이터와 출력

| YOLO ID | 클래스 | 의미 | 원본 박스 | 최종 박스 |
|---:|---|---|---:|---:|
| 0 | outsole | 밑창·아웃솔 | 726 | 358 |
| 1 | heel lining | 뒤꿈치 안쪽 안감 | 3,808 | 2,101 |
| 2 | not_sneakers | 운동화가 아닌 신발 | 15 | 6 |
| | **합계** | | **4,549** | **2,465** |

원본 등록 12,599장 중 **1,465장**을 사용합니다. 매칭되지만 라벨 없는 사진은 4,936장, 사진이 없는 등록 이미지는 6,198장입니다. 사진이 없는 이미지 중 라벨이 있는 것은 1,321장입니다. 최종 train 1,222장, val 131장, test 112장입니다.

사용 사진은 모두 512×512입니다. 라벨은 고해상도 사진 기준 좌표이므로 라벨의 너비·높이로 정규화하여 축소 사진에 대응합니다. 사용 사진의 종횡비 불일치는 없지만, 크롭·회전 여부와 실제 박스 위치는 육안 검토가 필요합니다.

출력은 부위별 `클래스, confidence, 박스 좌표`입니다. 현재 라벨은 손상 종류·심각도·정상 여부를 별도로 표현하지 않습니다. 박스가 없다는 이유만으로 정상 운동화라고 판정하지 않습니다.

### 학습 설계

YOLO11n을 원본 3개 클래스로 미세조정하여 기준 모델을 만듭니다. 뒤꿈치 안감에 라벨이 집중되어 있으므로 부위별 성능을 별도로 분석합니다. 작은 손상이나 경계가 모호한 영역을 왜곡하지 않도록 증강을 약하게 설정하고, mosaic 확률은 data1보다 낮은 0.1로 사용합니다.

향후에는 not_sneakers를 제외하고 손상 2종만 학습하는 실험을 비교할 수 있습니다. 이 실험은 클래스 재매핑과 별도 데이터 설정을 먼저 준비해야 하며 현재 기본 파이프라인에는 포함되지 않습니다. 입력 크기 확대와 모델 크기 변경도 각각 독립 실험으로 비교합니다.

### 인퍼런스 설계

data2 전용 best.pt를 사용하여 입력 사진 전체에서 손상 부위를 탐지합니다. 현재 독립 실행 코드는 data1의 운동화 박스로 자동 크롭하지 않습니다. 입력은 운동화 사진을 기본으로 하며, 원본 예외 클래스 출력도 보존합니다.

val에서 정한 confidence를 사용하고 task1과 동일한 형식으로 결과를 저장합니다. 다른 task의 가중치·임계값을 실수로 사용하지 않도록 클래스명과 가중치 해시를 확인합니다.

### 평가와 초기 목표

| 지표 | 목표 | 평가 범위 |
|---|---:|---|
| mAP@0.5 | ≥ 85% | 손상 2종 평균 |
| mAP@0.5:0.95 | ≥ 50% | 손상 2종 평균 |
| Macro-Precision | ≥ 85% | 손상 2종 평균 |
| Macro-Recall | ≥ 90% | 손상 2종 평균 |
| Macro-F1 | ≥ 87% | 손상 2종 평균 |
| outsole Recall | ≥ 90% | 밑창 미탐 억제 |
| heel lining Recall | ≥ 90% | 뒤꿈치 안감 미탐 억제 |
| 정상 이미지 오탐률 | ≤ 5% | 별도 확인된 정상 운동화 평가 세트 |

val에서 손상 2종 각각 Recall 90%를 만족하는 confidence 후보 중 두 종류의 Macro-Precision이 가장 높은 값을 선택합니다. not_sneakers는 손상 부위가 아니므로 주 평가 평균에서 제외하고 클래스별 결과에 별도로 기록합니다.

현재 outsole의 test 정답은 17개로 적고, not_sneakers는 train 6개·val/test 0개입니다. not_sneakers의 평가 결과는 N/A로 처리합니다. 정상 오탐률은 정상 여부가 검수된 사진을 최소 200장 확보한 후 측정하며, 현재 손상 양성 데이터만으로는 측정할 수 없습니다.

### 학습 전후 EDA

학습 전에는 고해상도 좌표를 축소 사진에 대응한 박스를 우선 검토합니다. 부위별 박스 크기·위치와 날짜 분포, 작은 영역의 비중, 뒤꿈치 안감 편중 및 사진 누락을 분석합니다.

학습 후에는 손상 미탐과 잘못된 위치의 탐지를 우선 확인합니다. 작은 부위의 Recall, outsole과 heel lining의 혼동, 배경·정상 영역 오탐을 검토합니다. 확인된 정상 사진 세트가 있으면 이미지 단위 오탐률을 별도로 계산합니다.

| 모델 | yolo11n.pt |
| 입력 크기 | 512 |
| 최대 epochs | 100 |
| early stopping patience | 20 |
| batch | 8 |
| workers | 0 |

| deterministic | True |

CPU를 기본 실행 장치로 두며 CUDA 지원 환경은 `--device 0`으로 실행합니다. deterministic 설정은 재현성을 높이기 위한 것이며, 하드웨어와 라이브러리 버전이 다른 환경에서 완전히 같은 결과를 보장하지는 않습니다.

## 6. 공통 평가 설계

### AP 평가와 운영 임계값 평가를 분리

- **AP/mAP:** 낮은 후보 수집 confidence 0.001로 예측을 보존하여 여러 confidence에 걸친 성능을 계산합니다. mAP@0.5는 IoU 0.50, mAP@0.5:0.95는 IoU 0.50~0.95의 10개 기준을 사용합니다.
- **고정 confidence의 Precision·Recall·F1:** val에서 선택한 임계값으로 후보를 필터링합니다. confidence 순으로 클래스가 같은 정답과 IoU ≥ 0.50인 예측을 일대일 대응시킵니다. 중복 탐지는 FP, 대응되지 않은 정답은 FN입니다.
- confidence 선택 후보는 0.05~0.95를 0.05 간격으로 탐색합니다. Recall 조건을 만족하지 못하면 탐색용 대체값과 `constraints_met=false`를 저장합니다.
- NMS IoU 기본값은 0.7이며 중복 예측 제거용 설정입니다. 정답 판정 IoU 0.50과는 다른 설정입니다. 최대 예측 수는 이미지당 300개입니다.

### 평가 데이터 사용 원칙

모델과 임계값은 val에서 선택하고 test에서는 확정된 설정을 사용합니다. 임계값 파일은 가중치 SHA256, 입력 크기, NMS IoU, max_det를 기록합니다. 다른 가중치나 다른 설정으로 사용하면 오류를 냅니다.

표본 없는 클래스는 N/A입니다. 목표 비교표는 클래스별 정답 50박스·20사진 미만을 `INSUFFICIENT_SAMPLE`로 표시합니다. 이 표본 기준은 프로젝트 내부의 최소 참고 기준이며 통계적 충분성을 보증하지 않습니다. `MET_OBSERVED`는 관측 점수가 목표에 도달했다는 뜻이며, 독립 촬영 날짜와 라벨 품질까지 확인한 최종 합격 판정은 아닙니다.

촬영 날짜 단위 bootstrap 신뢰구간은 평가 계획에 있는 향후 보강 항목이며 현재 코드에는 구현하지 않았습니다. 지표별 정의와 클래스별 세부 목표는 [평가 계획](evaluation_plan.md)을 참고합니다.

### 속도 평가

`--benchmark`를 지정하면 batch 1에서 워밍업 10회 후 200회 측정합니다. 메모리의 입력에서 전처리·추론·후처리 시간을 포함하고, 파일 읽기·이미지 디코딩·최초 모델 로딩은 제외합니다. CUDA는 동기화하여 측정합니다. 표본이 200장 미만이면 사진을 반복합니다.

평균·중앙값·p95를 기록하고 초기 목표는 각 task p95 ≤ 1초입니다. 최종 실행 장치가 정해지면 장치와 함께 기준을 확정합니다.

| 단계 | 구현 내용 | 저장 결과 |

| 학습 전 | 해상도, 평균 밝기, 이미지당 객체 수 | images.csv, distributions.png |
| 학습 전 | 정규화 박스 중심·면적·종횡비 | boxes.csv, distributions.png |
| 학습 전 | SHA256 중복과 동일 dHash의 유사 사진 후보 | checks.json |
| 학습 전 | 클래스별 정답 박스를 그린 사진 | label_samples/ |
| 학습 후 | 클래스별 AP·고정 confidence P/R/F1 | class_ap.png, metrics.png |
| 학습 후 | 상대 박스 크기별 Recall | size_recall.csv |
| 학습 후 | 목표 대비 수치·표본 부족 상태 | class_target_comparison.csv, overall_target_comparison.csv |

| 학습 후 | 학습/검증 손실과 mAP 곡선 | training_curves.png |
| 학습 후 | 라이브러리 PR 곡선과 혼동행렬 | native_*.png |

상대 박스 면적은 이미지 면적 대비 1% 미만, 1~10%, 10% 초과로 나눕니다. 이는 프로젝트 내부 구간이며 COCO의 크기 구간 정의가 아닙니다. 박스 시각화는 초록색 정답, 빨간색 예측입니다.

학습 전 라벨 샘플은 클래스별 최대 20장, 학습 후 사례는 오류 유형별 최대 20장을 기본으로 저장합니다. 모든 소수 클래스의 오류가 샘플에 포함된다고 보장하지 않으므로 클래스별 통계와 원시 예측도 함께 확인합니다. 동일 dHash는 유사 사진의 후보이며 모든 근접 중복을 검출하는 방법은 아닙니다.

라이브러리 PR 곡선·혼동행렬은 AP 평가 설정을 사용합니다. 운영 임계값의 오류 사례·P/R/F1과 혼용하지 않습니다.

## 8. 코드 구조와 실행 순서

```text
men_dii/
  prepare_data.ps1
  verify_data.ps1
  train.py                   # 공통 학습 진입점, --task 사용
  run_task.ps1               # task별 단계 자동 실행
  requirements.txt
  pipeline/
    run.py                   # 데이터·학습·예측·평가·EDA 공통 구현
    metrics.py               # 고정 임계값 박스 매칭과 지표 계산
  scripts/
    data1/                   # data2도 동일한 5개 파일
      pre_eda.py
      train.py
      evaluate.py
      post_eda.py
      infer.py
    data2/
  datasets/data1/             # data2도 동일한 YOLO 구조
  artifacts/                 # 실행별 결과, 기존 출력 덮어쓰기 방지
  tests/
  docs/
```

1. 환경 준비 및 `verify_data.ps1`로 데이터 검증.
2. task별 `pre_eda.py` 실행 후 라벨 샘플과 중복 후보 검토.
3. `train.py`로 task별 best.pt 생성.
4. `evaluate.py --split val --select-threshold`로 임계값 선택.
5. `post_eda.py`로 val 결과 분석. 개선은 새 실행 폴더에서 val 기준으로 수행.
6. 모델과 설정을 확정한 뒤 `evaluate.py --split test --threshold-config ...` 실행.
7. `post_eda.py`로 test 결과와 목표 대비표 생성.
8. `infer.py`로 새 사진·폴더·영상 예측.

자동 실행 스크립트는 val Recall 조건을 만족하지 못하면 val 결과 EDA까지 저장하고 test 전에 중단합니다. 사전 EDA 검토는 자동 실행 전에 사람이 수행해야 합니다. 단계별 실제 명령어는 [실행 가이드](pipeline_guide.md)에 있습니다.

## 9. 향후 두 모델 연결 설계

향후 전체 시스템은 `data1 운동화 탐지 → data2 손상 부위 탐지`로 연결합니다. 운동화 박스로 크롭할 경우 전체 사진과 입력 분포가 달라지므로 별도 비교 실험이 필요하고, 예측 박스는 원본 좌표로 복원해야 합니다.

연결 모델의 초기 목표는 손상 부위별 최종 Recall ≥ 85%, 전체 처리시간 p95 ≤ 2초입니다. data1이 운동화를 놓쳐 data2가 실행되지 못한 경우도 손상 미탐으로 셉니다. 두 모델 Recall을 단순히 곱하지 않고 두 task의 라벨이 함께 검수된 독립 사진에서 직접 평가합니다.

**현재 연결 인퍼런스와 연결 성능 평가는 구현되지 않았습니다.** 현재 코드는 두 task의 독립 모델 개발과 평가까지 지원합니다.
