# 개발용 자연어 추론 추적기

검출 결과가 어느 입력 뷰·query 슬롯·후처리 결정에서 나왔는지 기록하고, 측정된 사실을 한국어 문장으로 남깁니다. 실제 서비스와 분리된 개발용 명령입니다. 모델의 내면 생각이나 사고 과정을 생성하지 않습니다.

## 기록 범위

1. 원본 크기와 입력 뷰: 전체 프레임, 선택 시 겹치는 타일 4개.
2. 실제 전처리 텐서의 크기·값 범위와 역정규화한 입력 이미지.
3. 특징 추출기 출력 형태와 원시 query별 클래스 점수·박스.
4. 후처리된 검출을 실제 원시 query에 좌표·점수로 연결한 ID. 불일치하면 임의로 연결하지 않고 실패합니다.
5. 타일 좌표 복원, 중복 억제의 상대 후보 ID·IoU, 최대 검출 수 제외, 표시 임계값.
6. 최종 선택된 query 슬롯의 디코더 단계별 클래스 점수·박스. 동일 슬롯이 매 단계 동일한 의미의 객체를 가리킨다고 가정하지 않습니다.
7. 해당 사진이 기존 val에 속할 때만, 추론이 끝난 뒤 정답과 평가한 결과.
8. 입력 일부를 흐리는 5개 실험과 선택적 격자 민감도 실험. 고정 query 점수뿐 아니라 박스 이동과 같은 위치의 대체 후보 점수도 기록합니다.

특징 채널이나 attention을 손상 개념으로 번역하지 않습니다. 자연어는 측정값을 템플릿에 넣어 작성하며 추가 언어모델 API·이미지 업로드를 사용하지 않습니다. 가설은 별도의 `kind=hypothesis` 이벤트로 저장합니다. 점수는 보정된 확률이 아닙니다.

## 실행 예

```powershell
.venv/Scripts/python.exe -u -m pipeline.inference_trace `
  --source datasets/data2/images/val/20240604_104903.jpg `
  --weights artifacts/no_new_data_20261016_014558/data2_tiles30/train/fit/best.pth `
  --output artifacts/inference_traces/front_toe_20261016_v2 `
  --tiled --occlusion
```

`--focus-class 0`은 밑창이며, `--focus-rank 0`은 최종 표시된 해당 클래스 중 점수가 가장 높은 검출을 선택합니다. 다른 박스는 순위로 선택합니다. `--conf` 기본값은 0.25입니다. `--tiled`를 생략하면 전체 프레임만 추론합니다. `--occlusion`을 생략하면 5개 영역 흐림 비교만 실행합니다. 격자는 기본 패치 96px·간격 64px·가우시안 흐림 반경 12입니다.

현재 `--match-rule` 기본값은 요청에 따른 `any_overlap`입니다. 같은 클래스 정답과 교집합 면적이 조금이라도 있으면 정탐으로 평가합니다. 예전 IoU≥0.5 보고서를 재현하려면 `--match-rule iou50`을 지정합니다. 평가 기준을 바꿔도 모델 점수·출력 박스는 바뀌지 않습니다. 상세 정의는 `docs/overlap_evaluation.md`에 있습니다.

출력 폴더가 이미 있으면 덮어쓰지 않습니다. 새로운 폴더를 사용합니다. 기존 데이터셋의 test 폴더 사진은 탐색용 디버깅에서 차단합니다. 다른 위치에 복사된 test 사진까지 식별하는 접근 제어는 아니므로 사용자가 val 또는 별도 개발 이미지만 지정해야 합니다.

## 사진 하나의 여러 검출을 모두 추적

`--all-detections`를 추가하면 임계값 이상인 모든 검출을 클래스별로 나누지 않고 박스별로 추적합니다. 한 사진에 밑창·안감이 함께 있거나, 밑창 박스가 여러 개 있어도 각각 별도 보고서를 만듭니다. 모델은 한 번 로딩해 재사용하며 각 항목에서 동일한 검출이 재현되는지 확인합니다.

상위 `report.md`는 번호가 붙은 전체 검출 그림과 항목별 보고서 링크를, `index.json`은 항목별 상태·클래스·점수·좌표를 담습니다. 각 `target_번호_클래스/`에 자연어 기록과 입력 변경 실험이 들어갑니다. 이 모드에서 `--focus-class`, `--focus-rank`는 사용하지 않습니다. `--occlusion`까지 함께 지정하면 모든 검출에 격자 실험을 수행하므로 검출 수에 비례해 오래 걸립니다.

다른 사진에서 관찰한 동일 손상을 병합하는 기능은 별도입니다. 여러 박스가 같은 실제 손상의 조각·중복일 수 있으므로, 검출 개수를 실제 손상 개수나 견적 항목 개수로 확정하지 않습니다. 일반 평가 명령에 자동 연결된 상태는 아니며 개발용 추적 명령의 옵션입니다.

## 산출물

- `events.jsonl`: 실행 중 한국어 단계 기록. 이벤트 ID와 원시 근거를 포함합니다.
- `trace.json`: 원시 후보·디코더 출력·병합 계보·변형 실험·가중치와 이미지 해시.
- `report.md`: 관측 사실, 단계별 점수 표, 입력 변경 결과, 원인 가설을 구분한 보고서.
- `original.png`, `selected_prediction.png`: 원본과 추적 대상 표시.
- `inputs/`: 각 뷰에서 모델에 들어간 실제 픽셀 입력의 역정규화 이미지.
- `experiments/`: 영역별 흐림 실험 사진.
- `occlusion.png`, `occlusion_score_drop.npy`, `occlusion_spatial_score_drop.npy`: 선택적 고정 슬롯 및 동일 위치 검출의 민감도 그림·수치.

## 해석 한계

- 출력 위치를 찾은 과정의 기록이며 사람이 이해하는 추론 논증을 읽어낸 결과가 아닙니다.
- 중간 디코더 점수는 관측용입니다. 중간 단계마다 운영 임계값으로 손상을 판정하거나 제거한 것은 아닙니다.
- 흐림은 질감·경계·색상 정보를 동시에 바꿉니다. 다른 크기의 영역에 대한 점수 변화량을 독립적인 원인 기여도로 간주하지 않습니다.
- 변형 후 같은 query가 이동하거나 다른 query가 검출을 대신할 수 있습니다. 고정 슬롯 점수만으로 검출이 사라졌다고 결론 내리지 않습니다.
- 격자 실험은 선택 후보의 출처 뷰 한 개를 대상으로 합니다. 타일 앙상블 전체의 원인 기여도 지도가 아닙니다.
- 기여 실험은 지도가 밝다는 이유만으로 모델이 그 부위를 문제로 인식했다고 확정하지 않습니다.
- 현재 클래스는 부위 중심입니다. 결과를 밑창 벌어짐·오염·마모 같은 학습하지 않은 손상 종류로 자동 설명하지 않습니다.
- 같은 오류 유형의 여러 사진과 정상 검출 사례에 반복해 비교한 뒤 개선 방향을 판단해야 합니다. 자동 라벨 수정이나 재학습은 수행하지 않습니다.

구현: `pipeline/inference_trace.py`. 기존 모델·라벨·서비스 코드는 바꾸지 않고 PyTorch hook을 설치했다가 실행 종료 시 제거합니다.
