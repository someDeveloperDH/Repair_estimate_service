# Task별 평가 방식과 목표 수치

작성일: 2026-10-14

이 문서의 수치는 **실측 결과가 아닌 프로젝트 초기 목표**입니다. 현재 데이터만으로 달성 가능성을 보장하지 않습니다. 첫 학습 결과를 기준으로 난이도를 확인하되, 테스트 결과를 보고 목표나 분할을 유리하게 바꾸지 않습니다. 목표를 수정하면 사유와 버전을 기록합니다.

## 1. 평가 대상

| 항목 | data1 | data2 |
|---|---|---|
| 목적 | 신발 위치와 종류 탐지 | 운동화 손상 부위 위치와 종류 탐지 |
| 원본 클래스 | 신발 종류 7개 | 손상 부위 2개 + not_sneakers |

## 2. 평가 지표 설명

### IoU: 예측 박스와 정답 박스가 얼마나 겹치는가?

`IoU = 두 박스의 교집합 면적 / 두 박스의 합집합 면적`

0이면 겹치지 않고, 1이면 위치와 크기가 일치합니다. 이 계획에서 Precision·Recall·F1을 계산할 때는 **클래스가 맞고 IoU ≥ 0.50**인 예측을 정답 후보로 봅니다. 정답과 예측은 일대일로 대응시키며, 동일 객체를 중복 탐지하면 추가 예측은 오탐입니다. 매칭 방식과 평가 프로그램 버전도 기록합니다.

IoU 0.50은 정답 판정 기준이지, 모델 전체의 목표 점수는 아닙니다. 위치 정확도는 아래 mAP@0.5:0.95로 함께 평가합니다.

### Precision: 모델이 탐지한 것 중 얼마나 맞았는가?

`Precision = TP / (TP + FP)`

- TP: 클래스와 위치가 맞아 정답에 대응된 예측.
- FP: 잘못된 종류, 위치 오류, 정답 없는 영역 또는 중복 탐지 등 잘못된 예측.
- 예: 100개를 탐지하여 90개가 맞으면 Precision은 90%입니다.

data1에서는 다른 신발을 운동화로 오분류하는 오류, data2에서는 손상 부위가 아닌 영역을 탐지하는 오류를 줄이는 데 관련됩니다. 현재 라벨이 있는 사진만으로 측정한 Precision은 별도 정상 사진에서의 오탐을 보장하지 않습니다.

### Recall: 실제 객체 중 얼마나 놓치지 않았는가?

`Recall = TP / (TP + FN)`

FN은 대응되는 정답 예측이 없는 실제 객체입니다. 실제 손상 박스 100개 중 90개를 찾으면 Recall은 90%입니다. data2에서는 손상 부위를 놓치는 것이 주요 실패이므로 Recall에 더 높은 우선순위를 둡니다.

### F1: Precision과 Recall의 균형이 좋은가?

`F1 = 2 × Precision × Recall / (Precision + Recall)`

한쪽만 높으면 F1은 낮아집니다. Precision 90%, Recall 90%면 F1은 90%입니다. F1은 같은 임계값에서 계산한 Precision·Recall을 사용합니다. 클래스별 F1을 계산한 뒤 평균하는 Macro-F1과 전체 객체를 합산한 F1은 다르므로 구분하여 보고합니다.

### AP@0.5 및 mAP@0.5: 탐지 신뢰도 전반에서 성능이 좋은가?

AP는 신뢰도 임계값을 바꿔 만든 Precision–Recall 곡선을 요약한 클래스별 점수입니다. AP@0.5는 IoU 0.50을 정답 기준으로 사용합니다. mAP@0.5는 클래스별 AP@0.5의 평균입니다. mAP 90%가 이미지의 90%를 정확히 분류했다는 뜻은 아닙니다.

클래스가 불균형한 상황에서도 클래스별 점수를 확인할 수 있습니다. 다만 정답 표본이 없거나 극소수인 클래스는 유효한 평가가 어렵습니다. 평균에 포함된 클래스를 항상 명시합니다.

### mAP@0.5:0.95: 위치를 엄격하게 봐도 탐지가 정확한가?

IoU 0.50부터 0.95까지 0.05 간격의 10개 기준에서 AP를 계산하고 클래스와 기준에 걸쳐 평균합니다. 신발 근처를 대략 찾는 것보다 정확한 박스 위치를 요구하므로 일반적으로 mAP@0.5보다 낮습니다. 최적 모델 선택의 기본 지표로 사용합니다.

### 혼동행렬과 오류 사례

종류 간 혼동, 미탐, 오탐을 분석합니다. data1은 formal↔heels 등 혼동이 많은 조합을 실제 결과에서 찾고, data2는 outsole↔heel lining의 혼동과 위치 오류를 확인합니다. 탐지에서는 배경의 모든 가능한 음성 박스를 셀 수 없으므로 일반 분류의 Accuracy나 TN 기반 지표를 주 지표로 사용하지 않습니다.

| mAP@0.5:0.95 | ≥ 65% | 엄격한 위치 정확도까지 포함 |

평균 목표와 클래스별 최소 목표를 모두 봅니다. 운동화 성능만 높아 전체 데이터의 오류가 가려지지 않도록 객체 수로 가중한 평균도 보조 지표로 함께 기록합니다.

## 4. data2 — 손상 부위 평가 목표

### 손상 2종에 대한 전체 목표

| 지표 | 초기 목표 | 적용 범위·의미 |
|---|---:|---|
| mAP@0.5 | ≥ 85% | outsole, heel lining 2종 평균 |
| mAP@0.5:0.95 | ≥ 50% | 손상 부위의 위치 정확도 포함 |

손상 부위가 신발 전체보다 작거나 경계가 모호할 수 있다는 가정으로 위치 정확도 목표를 data1보다 낮게 설정했습니다. EDA와 첫 학습에서 이 가정을 확인합니다.

### 클래스별 최소 목표

| 클래스 | AP@0.5 목표 | Precision 목표 | Recall 목표 | 현재 test 정답 박스 |
|---|---:|---:|---:|---:|
| outsole | ≥ 80% | ≥ 80% | ≥ 90% | 17 |
| heel lining | ≥ 90% | ≥ 90% | ≥ 90% | 184 |
| not_sneakers | ≥ 80% | ≥ 80% | ≥ 80% | 0 |

손상 2종의 목표 평균에서 not_sneakers는 제외하며, 이 점수를 3종 전체 mAP로 표기하지 않습니다. 3종 기준 모델을 학습하면 평가 가능한 클래스와 제외 클래스를 별도로 기록합니다.

**not_sneakers 목표는 데이터 추가 후 적용하는 조건부 목표입니다.** 현재는 학습 박스가 6개이고 val/test 정답이 없어 평가 불가(N/A)입니다. outsole도 test가 17개뿐이라 현재 결과로 안정적인 성능을 확정하지 않습니다.

### 정상 사진에서의 오탐 목표

| 지표 | 정의 | 초기 목표 |
|---|---|---:|
| 정상 이미지 오탐률 | 손상 2종을 1개 이상 잘못 탐지한 정상 사진 수 / 전체 확인된 정상 사진 수 | ≤ 5% |

현재 데이터에는 확인된 정상 평가 세트가 없어 **측정 불가**입니다. 정상 여부가 검수된 운동화 사진을 최소 200장 확보한 뒤, 검증에서 고정한 손상 탐지 임계값으로 측정합니다. not_sneakers 탐지는 이 손상 오탐률에 포함하지 않습니다. 200장 중 최대 10장이라는 관측 기준이며, 모집단 오탐률이 5% 이하임을 통계적으로 보증하는 기준은 아닙니다.

## 5. 실제 평가 절차와 합격 판정

1. **라벨 검수:** 클래스별 예시와 좌표 변환 결과를 육안 확인하고 오류를 수정합니다. 라벨 검수 없이 높은 점수만으로 품질을 판단하지 않습니다.
2. **분할 확정:** 촬영 날짜를 묶어 중복을 줄이고 유사 이미지도 점검합니다. 부족한 클래스를 위해 분할을 수정하면 모델 학습 전에 새 버전으로 고정합니다.
3. **표본 보강:** 프로젝트 내부 기준으로 각 클래스에 val/test 각각 최소 50개 정답 박스와 20장 이상의 서로 다른 사진, 여러 촬영 날짜를 확보하는 것을 1차 목표로 합니다. 이는 충분한 통계적 검정력을 보장하는 수치가 아니며, 신발 개체 독립성도 확인해야 합니다.
4. **검증에서 선택:** 모델과 입력 크기는 val mAP@0.5:0.95를 기본으로 비교합니다. confidence 임계값도 val에서 정합니다. data1은 Macro-F1을 우선하고 sneakers Recall 95%를 확인합니다. data2는 손상 2종 각각 Recall 90%를 만족하는 후보 중 Macro-Precision이 가장 높은 임계값을 선택합니다. 제약을 만족하는 후보가 없으면 미달로 기록합니다.
5. **설정 고정:** 가중치, confidence, NMS IoU, 이미지 크기, max detections, 라이브러리 버전과 하드웨어를 기록합니다. NMS IoU는 중복 예측 제거 설정으로, 정답 매칭의 IoU 0.50과 구분합니다.
6. **최종 테스트:** 고정한 임계값에서 클래스별 P/R/F1을 계산합니다. AP/mAP는 낮은 점수의 후보도 보존하여 신뢰도 곡선을 계산하는 별도 평가로 수행합니다. 운영 임계값으로 예측을 먼저 잘라 AP를 왜곡하지 않습니다. 라이브러리가 자동 선택한 best-F1 P/R을 고정 임계값의 결과로 혼용하지 않습니다.
7. **판정:** 평가 표본이 갖춰지고 전체 및 클래스별 목표를 모두 만족하면 해당 범위에서 통과입니다. 표본 부족이나 정답 부재는 통과가 아니라 '판정 보류/N/A'로 기록합니다. 테스트를 반복 보며 설정을 조정했다면 새 독립 테스트 세트가 필요합니다.

성능의 불확실성은 가능하면 촬영 날짜 단위 재표집(bootstrap)으로 95% 신뢰구간을 함께 보고합니다. 촬영 날짜나 표본이 너무 적으면 구간도 불안정할 수 있음을 명시합니다. 목표 통과는 우선 관측 점수 기준이며, 신뢰구간 하한까지 목표를 넘었다고 주장하지 않습니다.

## 6. 두 모델 연결 평가와 처리 속도

### 연결 평가

data1이 운동화를 판별하고 data2가 해당 운동화 손상을 찾는 전체 흐름에서 **손상 부위별 최종 Recall ≥ 85%**를 초기 목표로 둡니다. data1이 운동화를 놓쳐 data2가 실행되지 않은 경우도 미탐으로 집계합니다. 실제 구현의 전체 이미지/크롭 입력 방식을 고정하고, 크롭을 사용하면 좌표를 원래 사진 기준으로 복원하여 평가합니다.

두 task의 라벨이 함께 검수된 독립 사진으로 직접 측정합니다. 두 모델의 Recall을 단순히 곱한 값은 최종 측정 결과로 사용하지 않습니다. 현재 공통 평가 라벨의 완전성은 확인하지 않았으므로 이 목표도 조건부입니다.

### 속도

초기 사용성 목표는 **각 task 이미지 1장당 전체 처리시간 p95 ≤ 1초**, 두 모델 연결은 **p95 ≤ 2초**로 설정합니다. 이는 실시간 영상 목표가 아닌 사진 처리의 임시 목표입니다. 최종 실행 장치가 확정되면 하드웨어와 함께 목표를 다시 고정합니다.

배치 1, 입력 크기 512, 동일 하드웨어에서 워밍업 후 최소 200장을 측정합니다. 전처리·모델 추론·후처리를 포함하고 모델 최초 로딩과 디스크 읽기는 별도 기록합니다. GPU는 동기화하여 측정하고 평균·중앙값·p95를 보고합니다. 현재는 하드웨어와 실행 환경이 확정되지 않아 속도 합격 판정은 보류합니다.

## 7. 결과 EDA 및 보고 항목

- 학습/검증 손실 곡선: 과적합과 학습 불안정 확인. 손실값 자체의 일률적인 합격 수치는 정하지 않습니다.
- 클래스별 AP·P/R/F1: 목표 대비 차이와 정답 이미지/박스 수를 함께 표기.
- PR 곡선 및 confidence별 P/R/F1: 최종 임계값과 선택 근거 표시.
- 혼동행렬: 종류 간 혼동, 미탐, 오탐을 수와 비율로 분석.
- 크기별 분석: 실제 사진 기준 박스 면적 비율이 1% 미만/1~10%/10% 초과인 그룹으로 나누어 Recall을 비교. 이는 프로젝트 내부 구간이며 COCO의 small/medium/large 정의가 아닙니다.
- 육안 오류 분석: 클래스마다 가능하면 성공·오탐·미탐 각 20건씩 확인하고, 20건 미만이면 전체 건수를 확인. 작은 부위, 어두움, 가림, 위치 오류, 라벨 오류 등을 태깅.
- 데이터 부족·미평가 항목: 별도 표로 명시하고 실제 성능 수치와 혼동하지 않기.
